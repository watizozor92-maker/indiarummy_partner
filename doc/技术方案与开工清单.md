## 1. 推荐技术路线

推荐采用独立应用，不直接在旧 `admin` 项目中增加模块：

```text
浏览器管理界面
  -> Partner Web/API（ThinkPHP 6.1.2 安全补丁版）
       -> indiarummy_game（业务查询与配置）
       -> partner 自有后台表（账号、权限、白名单、审计）
       -> IndiaRummy 内部管理 API（运行时加载与状态查询）
```

### 后端

- ThinkPHP 6.1.2，PHP 8.2；
- 回移官方 6.1.5 异常模板 XSS 修复，并通过 Composer 自动应用；
- 框架严格锁定为 6.1.2，禁止自动升级到受严重反序列化公告影响的 6.1.3 及以上版本；
- 移除依赖存在安全公告的 `think-filesystem/Flysystem 1.x`；
- 每次构建执行 `composer audit` 和补丁应用校验；
- 新建干净项目，不复制旧项目的 `vendor`、缓存和历史业务代码；
- 控制器只负责协议与权限，业务规则进入 Service，查询进入 Repository；
- 所有接口返回统一 JSON；
- 管理端会话使用安全 Cookie，服务端保存登录状态；
- MySQL 5.7 兼容，JSON 字段仅用于不可变配置快照，不把高频筛选字段藏进 JSON；
- 使用 `partner`（后台自有数据）和 `game`（游戏业务数据）两个显式数据库连接。

### 管理界面

已确定使用“服务端页面 + 更新版 Layui”的轻量方案，部署简单，也便于参考现有后台的交互经验。

不建议直接继续使用旧后台中的 Layui 2.3.0，其版本过旧；旧页面只作为交互和字段参考。

### 图表

- ECharts；
- 金额与百分比格式统一封装；
- 图表与列表使用同一统计接口和口径。

## 2. 为什么不直接复制现有 admin

现有 `admin` 为 ThinkPHP 6.0.7，功能很多但历史边界较宽。直接复制会同时带入：

- 大量与渠道游戏运营无关的模块；
- 旧权限配置和部分 `notNeedRight` 放行接口；
- API 密钥明文展示风险；
- 页面控制器中混合查询、配置编译和运行时调用；
- 旧版 Layui 和大量不可追踪的静态资源；
- N+1 查询与跨月分页等历史实现。

新项目可以复用业务思想和必要代码片段，但必须重新建立租户隔离、权限、审计和发布边界。

## 4. 模块边界

### Identity

后台账号、角色、权限、登录、会话、密码策略。

### Tenant

从会话解析 `channel_id`，统一给所有商户查询追加租户条件。平台管理员使用显式的商户选择上下文。

### Merchant

商户资料、API 密钥生命周期、币种、线路、钱包模式、游戏授权、IP 白名单。

### Player

玩家列表、玩家详情、余额与周期统计。

### Round

跨月游戏记录检索、详情、回放与归属快照。

### Statistics

按商户/游戏/币种/时间聚合，统一 RTP、中奖率和利润口径。

### GameControl

预设、渠道配置、库存、预览、发布、加载确认、版本历史和回滚。

### Audit

敏感读取和所有写操作的审计。

## 5. 发布事务边界

数据库事务不能覆盖远程 Skynet 调用，因此配置发布采用可恢复状态机：

```text
DRAFT
  -> VALIDATED
  -> PENDING_LOAD
  -> LOADED
       或 LOAD_FAILED
```

流程：

1. 校验请求版本和授权范围；
2. 生成不可变修订版本；
3. 同一数据库事务内更新 profile 为 `pending` 并写审计；
4. 事务提交后调用内部加载 API；
5. 根据运行时响应更新为 `loaded` 或 `failed`；
6. 超时任务可安全重试相同版本；
7. 回滚也是发布一个新版本，不覆盖历史版本。

## 6. 安全基线

- 登录前校验后台 IP 白名单；
- 密码使用 PHP `password_hash` 支持的强哈希；
- Cookie 设置 `HttpOnly`、`Secure` 和合适的 `SameSite`；
- 登录失败限流、验证码和会话轮换；
- 写接口启用 CSRF 防护；
- 商户接口忽略请求中的任意 `channel_id`；
- 统一参数验证，排序字段采用白名单；
- API 密钥加密保存或使用不可逆摘要，列表只展示末四位；
- 预览、发布、回滚、库存调整和导出均写审计；
- 内部管理 API 使用独立网络、签名、时间戳和重放保护。

## 7. 测试策略

必须优先覆盖：

- 商户 A 无法读取或修改商户 B 数据；
- 在查询参数中伪造 `channel_id` 无效；
- 平台角色与商户角色权限矩阵；
- 多币种不会错误合计；
- 配置并发发布的版本冲突；
- 远程加载失败后的状态与重试；
- 回滚生成新版本且可再次回滚；
- 跨月记录分页稳定；
- 密钥、白名单和导出审计完整。
