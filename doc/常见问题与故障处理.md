# 常见问题与故障处理

## 无法登录后台

依次检查：

1. 账号和密码是否正确。
2. 账号、商户是否处于启用状态。
3. 当前出口 IP 是否在所属商户白名单中。
4. 连续输错密码后账号是否处于临时锁定状态。
5. 反向代理是否把真实客户端 IP 正确传递给应用。

## IP 白名单怎么填写

- 单个 IPv4：`203.0.113.10/32`
- IPv4 网段：`203.0.113.0/24`
- 所有 IPv4：`0.0.0.0/0`
- 所有 IPv6：`::/0`

`0.0.0.0/0` 和 `::/0` 会基本取消 IP 防护，只建议临时测试使用。生产环境应配置固定出口 IP。

## 页面菜单不显示

菜单会根据账号角色和平台授权动态显示。商户看不到库存管理，通常是库存查看权限尚未授权；看不到库存流水或调整申请，说明对应的流水或调整权限未开启。

## 游戏调控列表没有编辑按钮

`merchant_viewer` 永远不显示编辑按钮。`merchant_admin` 还需要平台授予对应游戏的调控权限。平台默认账户用于维护平台方案，不等同于商户专属配置。

## 精确预览提示运行端未配置

确认后台的 `INTERNAL_GAME_API_URL`、`INTERNAL_GAME_API_SECRET` 与游戏 API 进程的 `PARTNER_CONTROL_API_SECRET` 一致，并确认游戏 API 与 master 服务已经启动且加载了最新代码。

## 发布后目标值没有变化

刷新游戏调控列表，确认“当前方案”是否显示商户专属，并核对目标 RTP / 中奖率是否为发布后的实际值。如果运行端加载失败，配置可能已保存但尚未生效，应检查加载状态和错误信息。

## 实际 RTP 与目标 RTP 不一致

目标 RTP 是长期概率目标。局数少、投注量低、出现高倍结果或活动场景时，短期实际 RTP 可能显著偏离。应扩大日期范围，并结合局数、投注、派彩、场景和玩家调控记录分析。

## 当前场景是如何判定的

```text
有效库存 = 真实库存 - 活动可用预算 - 活动预留 - 待结算负债
库存比例 = 有效库存 ÷ 目标库存
体验分 = 体验预算 ÷ 风险单位
```

系统按优先级从高到低检查场景条件，首个满足条件的场景成为账户基础场景。活动、新手流程和玩家调控可能在具体开局时覆盖基础场景。

## 调整库存后可用库存为什么不同

人工调整的是“真实库存”，可用库存还会扣除活动预算、活动预留和待结算负债，所以两者不一定相等。提取库存时，系统禁止提取后无法覆盖已承诺金额的操作。

## 库存调整为什么进入审批

- `request` 模式下所有调整都需要审批。
- `direct` 模式下，超过单笔额度或同一库存账户当日累计额度会自动转审批。
- `none` 模式下不能提交调整。

## 接口连接被拒绝

浏览器出现 `ERR_CONNECTION_REFUSED`，通常表示对应 HTTP 服务没有监听该地址和端口。确认后台 PHP 服务已启动、访问端口正确、防火墙未阻止，并区分后台端口和游戏内部 API 端口。

## 如何提交有效的问题信息

联系管理员时请提供：

- 出现问题的时间和账号角色。
- 页面名称、商户、游戏、币种及筛选日期。
- 玩家 ID、局号、流水 ID 或调控任务 ID。
- 页面提示和浏览器控制台错误。
- 是否可以稳定复现，以及复现步骤。

不要发送密码、完整 API Key、内部 API 密钥或数据库连接密码。
