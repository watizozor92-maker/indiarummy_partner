# 现有数据与接口盘点

> 本文记录从现有代码和 SQL 中确认的事实，用作新后台设计输入，不代表直接复用全部旧实现。

## 1. 商户主表

表：`indiarummy_game.d_channel_parter`

| 字段 | 含义 | 新后台处理建议 |
| --- | --- | --- |
| `id` | 渠道商 ID | 作为 `channel_id` |
| `agency_uid` | 渠道注册名称 | 商户唯一代码 |
| `apikey` | API 密钥 | 禁止列表明文展示，后续设计轮换机制 |
| `show_name` | 显示名 | 商户名称 |
| `back_rate` | 返点 | 明确单位与生效规则后展示 |
| `phone` | 联系电话 | 敏感信息按权限展示 |
| `social_code` | 社交账号 | 敏感信息按权限展示 |
| `currency_code` | 结算货币 | 旧单值；实际多币种以映射表为准 |
| `credit_limit` | 信用额度 | 明确金额单位 |
| `purchase_limit` | 购买额度 | 明确金额单位 |
| `used_coin` | 当前使用金额 | 与钱包/结算口径核对 |
| `status` | 0 禁用、1 启用 | 登录与 API 接入均需检查 |
| `create_time` | 创建时间 | Unix 时间戳 |
| `update_time` | 更新时间 | Unix 时间戳 |

现有 `master/channelpartermgr.lua` 支持加载全部渠道、按 ID 获取、信用检查、余额更新及渠道重载。

## 2. 游戏控制预设

表：`s_slot_control_preset`

主键：`game_id + preset_key`。

保存每款游戏经校准的策略、设置和指标：

- `policies_json`：场景策略；
- `settings_json`：目标 RTP、库存与补奖设置；
- `metrics_json`：实测 RTP、中奖率和倍率指标；
- `version/status`：预设版本和启停状态。

商户后台只能读取已启用且已授权的预设，不直接编辑 JSON。

## 3. 已发布控制配置

表：`s_slot_control_profile`

当前主键是 `channel_id + game_id`，包含：

- `preset_key`；
- `override_json`；
- `effective_scenes_json`；
- `parent_version/version`；
- `status`；
- `load_status/load_error`。

运行库存按币种隔离，但 profile 主键不含 `currency_code`。结合 `master/slotinventorymgr.lua` 的 `configs[key(channel_id, game_id)]` 加载逻辑，已确认当前正式模型为：控制策略对同一渠道所有币种共用，库存与统计按币种隔离。新后台按真实模型实现，并在发布界面显著提示影响范围；本项目不擅自把 profile 改造成币种级配置。

## 4. 配置修订历史

表：`d_slot_control_revision`

保存发布后的完整快照、校验结果、操作者和 IP。唯一约束为：

```text
channel_id + game_id + version
```

回滚应读取历史快照并创建新的 profile 版本，不能直接复写旧版本。

## 5. 实时库存

表：`d_slot_inventory`

主键：

```text
channel_id + game_id + currency_code
```

核心字段：

- 真实库存 `cash_reserve`；
- 目标库存 `target_reserve`；
- 体验预算 `experience_budget`；
- 活动可用/预留预算；
- 未完成玩法负债 `pending_liability`；
- 已实现利润；
- 当前周期投注、派彩、局数与开始时间；
- 乐观版本 `version`。

## 6. 库存不可变流水

表：`d_slot_inventory_ledger`

已固化：渠道、游戏、币种、玩家、局号、投注、派彩、金额、库存前后值、体验预算前后值、场景、模式和事件详情。

这张表适合库存报表、控制效果分析和审计，不应被直接更新或删除。

现有索引支持：

- 渠道/游戏/币种/时间；
- 玩家/时间；
- 渠道/游戏/币种/玩家/局号。

## 7. 玩家体验状态

表：`d_slot_experience_state`

按 `channel_id + game_id + currency_code + uid` 保存扶持周期、补奖次数、付费局数、投注、派彩、期望值和待处理局号。

服务器 `slotinventorymgr.lua` 已有：

- `getExperienceAssist`；
- `getExperienceState`；
- 预算预留和结算逻辑。

该能力可用于合规的体验扶持和连续未中奖补偿，不等同于商户单玩家强制输赢。

## 8. 运行时接口

现有服务端确认存在：

- `reloadChannel`：重载渠道场景/控制配置；
- `reloadUser`：已返回 `user control has been removed`，不可作为新后台能力；
- `reloadConfig(channel_id, game_id)`；
- `getControlStatus(channel_id, game_id, currency)`；
- `getProfitSummary(...)`；
- `getProfitHourly(...)`；
- `setCashReserve(...)`；
- `resetControlData(...)`；
- `getExperienceState(...)`。

新后台不能直接暴露这些内部方法。应在内部管理 API 层加入身份认证、参数校验、幂等、审计和权限限制。

## 9. 现有 admin 可参考实现

### `ApiManager.php`

已有商户列表、密钥、玩家列表、商户编辑和统计查询。可参考字段与查询来源，但需修复租户边界、密钥展示和历史归属问题。

### `Gamecontrol.php`

已有预设初始化、配置编译、预览、发布、状态、利润、小时统计、库存调整、重置、历史和回滚。

其中值得保留的设计：

- 发布生成不可变版本；
- 保存后调用运行时重载；
- `load_status/load_error` 记录加载结果；
- 回滚通过再次发布完成；
- 预设指标来自实际游戏配置与数据集预览。

需要修正的边界：

- 多个动作列入 `notNeedRight`，新系统必须逐接口鉴权；
- profile 与库存的币种维度需要统一定义；
- 写入和远程加载之间需要可重试状态机；
- 商户只能选择授权预设，不能进入高级权重编辑。

## 10. 仍需盘点的数据

- 玩家主表及余额的权威来源；
- API 玩家外部 ID 映射；
- `d_desk_user_YYYYMM` 各版本字段与分表时间范围；
- 游戏 ID 到名称、图标、类型的权威配置；
- 商户游戏授权关系；
- `s_channel_currency` 和币种 profile 的完整现状；
- 钱包模式、线路和回调配置现状；
- 旧记录能否可靠回填 `channel_id`；
- 目标环境中实际执行的 SQL 版本。
