# 平台管理员操作手册

本手册适用于 `platform_admin`。平台管理员拥有跨商户查看、配置、授权和审批能力，所有关键操作都会进入审计日志。

## 登录与账号安全

1. 使用平台管理员账号登录渠道游戏运营中心。
2. 平台管理员固定属于 `channel 0`。
3. 登录同时受账号状态、密码和平台 IP 白名单约束。
4. 首次登录后建议通过顶部“修改密码”更换初始密码。
5. 不建议在生产环境使用 `0.0.0.0/0`；应配置管理员的固定出口 IP。

命令行创建平台管理员：

```text
php think partner:admin:create platformadmin --display-name="平台管理员" --role=platform_admin --channel=0 --ip="203.0.113.10/32"
```

## 运营总览

运营总览用于快速查看当前范围内的玩家、投注、派彩、平台利润和主要趋势。利润为正显示绿色，亏损显示红色，零显示黑色。发现异常后，应进入游戏记录、数据统计或库存流水进一步核对。

## 玩家管理

- 默认日期与筛选框显示的日期保持一致。
- 可按商户、玩家和日期范围查询。
- 玩家详情用于核对余额、状态及分币种的投注、派彩和利润。
- 玩家管理是只读查询；玩家级别调控应进入“玩家调控”。

## 游戏记录与数据统计

- 游戏记录按局展示投注、派彩、利润、游戏和币种，可查看单局详情或导出。
- 数据统计按时间、商户、游戏和币种聚合投注、派彩、局数、玩家数、利润及实际 RTP。
- 不同币种不得直接相加后当作同一货币金额；应分别核对。

## 商户管理

### 新增商户

新增商户时填写商户编码、名称、额度、币种、管理员初始密码和登录 IP。系统会同时生成 API Key、商户管理员账号及初始白名单。API Key 等敏感信息只显示一次，应立即安全保存。

信用额度和采购额度填写 `-1` 表示无限额度。默认币种必须包含在授权币种中。

### 编辑与授权

平台管理员可以：

- 修改商户资料、状态、信用额度和采购额度，并查看当前信用分 `used_coin`。
- 增减商户可用币种。
- 设置每个游戏可用的调控预设、自定义目标、发布及回滚权限。
- 设置库存可见范围、流水权限、调整模式、单笔额度和每日额度。
- 管理商户后台登录 IP 白名单。

## 游戏调控

游戏调控按商户和游戏管理。发布前先预览，核对目标 RTP、中奖率、运行端精确预览值和版本；发布后“当前方案”应显示商户专属或平台默认，“目标 RTP / 中奖率”显示实际已发布值。

商户未发布专属方案时继承平台默认方案。恢复平台默认会取消商户专属覆盖。调控改变游戏样本或模式权重，不会修改已经完成的历史记录。

## 玩家调控

玩家调控用于在有限时间、金额和局数范围内执行玩家级扶持或抑制。创建任务前核对商户、玩家、游戏、币种、目标金额、目标 RTP、最大局数和有效时间。任务可取消，但已完成的游戏结果不会回滚。

## 库存管理

### 库存总览

库存按“商户 + 游戏 + 币种”隔离。详情显示当前基础场景及判定公式：

```text
有效库存 = 真实库存 - 活动可用预算 - 活动预留 - 待结算负债
库存比例 = 有效库存 ÷ 目标库存
体验分 = 体验预算 ÷ 风险单位
```

系统按场景优先级从高到低检查，首个满足库存比例和体验分条件的场景成为当前基础场景。具体玩家的活动、新手或点控可能在开局时覆盖基础场景，最终以库存流水为准。

### 调整库存

- “补充库存”增加真实库存。
- “提取库存”减少真实库存。
- 金额始终填写正数，系统根据类型决定正负方向。
- 调整原因必须能够供财务和运营追溯。
- 平台管理员发起的调整直接执行；商户申请可按授权直接执行或进入审批。

### 审批与流水

审批前核对商户、游戏、币种、金额、原因、调整前后库存和额度。执行完成后，在库存流水中查找 `inventory_adjustment` 记录进行对账。

## 操作审计

操作审计用于追踪账号、时间、IP、动作、资源、执行结果和失败原因。涉及商户资料、权限、调控、库存或白名单的争议，应先通过审计日志确认操作者和请求结果。

## 日常检查建议

1. 检查运行端加载状态和失败信息。
2. 检查库存危险、预警账户及待审批调整。
3. 检查实际 RTP、利润和异常高倍记录。
4. 检查商户账号及白名单是否仍符合最小权限原则。
5. 定期核对审计日志和库存流水。
