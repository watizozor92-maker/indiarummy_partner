# 库存管理模块

库存管理从游戏调控中独立，所有数据按 `channel_id + game_id + currency_code` 隔离。

## 菜单与权限

- 库存总览：平台管理员查看全部；商户需获得库存显示授权。
- 库存流水：商户还需单独获得流水查看授权。
- 调整申请/审批：商户管理员按授权提交，平台管理员审批；平台管理员也可直接调整。
- 库存授权：仅平台管理员使用，可限制游戏、币种、额度和有效期。

商户权限同时受账号角色和 `partner_inventory_grant` 控制。未授权商户不显示库存菜单，直接访问页面或 API 时仍会被服务端拒绝。

## 调整模式

- `none`：禁止调整。
- `request`：始终生成待审批申请。
- `direct`：单次和同一“游戏 + 币种”库存账户的当日累计均在授权额度内时直接执行，超额自动转为待审批申请。

每次执行通过签名内部 API 调用游戏服务的 `adjustCashReserve`。游戏服务以增减额原子更新内存库存和数据库快照，并写入 `d_slot_inventory_ledger`，事件类型为 `inventory_adjustment`。调整后库存不得低于活动预算、活动预留和待结算负债的合计。

## 部署要求

1. 运行 ThinkPHP 迁移 `php think migrate:run`。
2. 后台配置 `INTERNAL_GAME_API_URL` 和 `INTERNAL_GAME_API_SECRET`。
3. 游戏 API 进程配置相同值的 `PARTNER_CONTROL_API_SECRET`。
4. 重启游戏 API 和 master 节点，使新的 `adjustcashreserve` 动作与 `adjustCashReserve` 命令生效。

内部 API 密钥未配置或运行端未更新时，查看功能仍可用，库存调整会记录为执行失败且不会修改库存。
