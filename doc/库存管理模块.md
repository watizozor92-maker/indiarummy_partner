# 库存管理模块

库存管理从游戏调控中独立，所有数据按 `channel_id + game_id + currency_code` 隔离。

## 菜单与权限

- 库存总览：平台管理员查看全部；商户需获得库存显示授权。
- 库存流水：商户还需单独获得流水查看授权。
- 调整申请/审批：商户管理员按授权提交，平台管理员审批；平台管理员也可直接调整。
- 库存授权：仅平台管理员使用，可限制游戏、币种、额度和有效期。

商户权限同时受账号角色和 `partner_inventory_grant` 控制。未授权商户不显示库存菜单，直接访问页面或 API 时仍会被服务端拒绝。

## 调整模式

- `none`：禁止调整。
- `request`：始终生成待审批申请。
- `direct`：单次和同一“游戏 + 币种”库存账户的当日累计均在授权额度内时直接执行，超额自动转为待审批申请。

每次执行通过签名内部 API 调用游戏服务的 `adjustCashReserve`。游戏服务以增减额原子更新内存库存和数据库快照，并写入 `d_slot_inventory_ledger`，事件类型为 `inventory_adjustment`。调整后库存不得低于活动预算、活动预留和待结算负债的合计。

## 如何使用“调整库存”

“调整库存”用于人工增加或减少指定“商户 + 游戏 + 币种”库存账户的真实库存。它不修改玩家余额，也不直接修改目标 RTP、中奖率或目标库存；游戏松紧应通过游戏调控功能管理。

操作时先在库存总览中找到对应账户并点击“调整”，然后填写：

- 调整类型：选择“补充库存”或“提取库存”。
- 金额：始终填写正数，系统根据调整类型自动决定增减方向，不要输入负数。
- 操作原因：填写可供财务和运营追溯的真实原因，例如“商户线下充值 5,000 CNY”“提取本周已结算利润”或“修正初始化库存”。原因会保存在调整记录和审计日志中。

两种调整类型的含义：

- 补充库存：增加真实库存，适用于商户入金、平台补充启动库存或修正少记金额。
- 提取库存：减少真实库存，适用于商户提取资金、平台收回库存或修正多记金额。系统会校验提取后的真实库存是否足以覆盖已承诺资金，不能提取的申请不会执行。

例如某个 CNY 库存账户当前真实库存为 `10,000`：

- 选择“补充库存”并填写 `5,000`，执行后真实库存变为 `15,000`。
- 选择“提取库存”并填写 `3,000`，执行后真实库存变为 `7,000`。

可用库存不一定等于真实库存，其计算方式为：

```text
可用库存 = 真实库存 - 活动可用预算 - 活动预留 - 待结算负债
```

例如真实库存为 `10,000`，活动可用预算为 `1,500`、活动预留为 `500`、待结算负债为 `500`，则可用库存为 `7,500`。因此补充或提取真实库存后，可用库存会按当前已承诺金额重新计算。

提交后的处理方式取决于库存授权：

- 平台管理员发起的调整直接执行。
- 商户处于 `request` 模式时，提交后进入待审批状态，平台管理员批准后才修改库存。
- 商户处于 `direct` 模式时，单笔金额和当日累计金额均未超过授权额度则立即执行；超过任一额度会自动转为待审批申请。
- 商户处于 `none` 模式时不能发起库存调整。

操作完成后，可在“调整申请/审批”中查看执行或审批状态，并在“库存流水”中核对对应的 `inventory_adjustment` 记录。

## 部署要求

1. 运行 ThinkPHP 迁移 `php think migrate:run`。
2. 后台配置 `INTERNAL_GAME_API_URL` 和 `INTERNAL_GAME_API_SECRET`。
3. 游戏 API 进程配置相同值的 `PARTNER_CONTROL_API_SECRET`。
4. 重启游戏 API 和 master 节点，使新的 `adjustcashreserve` 动作与 `adjustCashReserve` 命令生效。

内部 API 密钥未配置或运行端未更新时，查看功能仍可用，库存调整会记录为执行失败且不会修改库存。
